# Oh My Pi themes for Pi

Research snapshot: 2026-08-10

## Recommendation

Create `home/dot_pi/agent/packages/oh-my-pi-themes/` as a local Pi package. Put generated theme files in `themes/`. Vendor the 98 themes exported by Oh My Pi's `defaultThemes` registry. Do not vendor Oh My Pi's base `dark.json` and `light.json` by default. Pi already owns the `dark` and `light` names, so adding those two creates avoidable name collisions.

Use an explicit package manifest:

```json
{
  "name": "local-oh-my-pi-themes",
  "private": true,
  "keywords": ["pi-package"],
  "pi": {
    "themes": ["./themes/*.json"]
  }
}
```

Pi supports themes from package `themes/` directories and from `pi.themes` manifest entries. Local package paths in settings resolve relative to the settings file. Sources: [Pi package documentation](https://github.com/earendil-works/pi/blob/afae6a1a998dbdfacc1004cbd26c6c6a99395bb2/packages/coding-agent/docs/packages.md), [Pi theme documentation](https://github.com/earendil-works/pi/blob/afae6a1a998dbdfacc1004cbd26c6c6a99395bb2/packages/coding-agent/docs/themes.md).

## Schema comparison

Pi 0.84.1 requires 51 color tokens. It also accepts optional `thinkingMax` and `scrollbarThumb`. Its schema rejects unknown color and top-level properties. Sources: [Pi schema](https://github.com/earendil-works/pi/blob/afae6a1a998dbdfacc1004cbd26c6c6a99395bb2/packages/coding-agent/src/modes/interactive/theme/theme-schema.json), [Pi loader and variable resolver](https://github.com/earendil-works/pi/blob/afae6a1a998dbdfacc1004cbd26c6c6a99395bb2/packages/coding-agent/src/modes/interactive/theme/theme.ts).

Oh My Pi requires the same 51 common tokens. It then requires 15 more tokens: `pythonMode` and 14 `statusLine*` tokens. It accepts optional `thinkingMax`, but it has no `scrollbarThumb`. It also accepts a top-level `symbols` object. Sources: [OMP JSON schema](https://github.com/can1357/oh-my-pi/blob/45e12e5bb758198a920c6070e7e64cb33b21beac/packages/coding-agent/src/modes/theme/theme-schema.json), [OMP runtime schema](https://github.com/can1357/oh-my-pi/blob/45e12e5bb758198a920c6070e7e64cb33b21beac/packages/coding-agent/src/modes/theme/schema.ts).

Audit of all 100 OMP built-in source files found:

- All 100 contain every one of Pi's 51 required tokens.
- No file defines `thinkingMax` or `scrollbarThumb`.
- All 100 contain `pythonMode` and all 14 `statusLine*` tokens.
- 52 contain the legacy extra token `link`. In every case, it equals `mdLink`.
- 23 contain the legacy extra token `toolText`. Every file also has the required `toolOutput` token.
- `dark-poimandres` and `light-poimandres` contain unsupported top-level `symbols` data.

The `link` and `toolText` tokens are not in the current OMP schema or Pi schema. They are stale fields in some built-in files. The source schemas above are the authority for this comparison.

## Exact compatibility transform

Apply these rules to each vendored theme:

| OMP input                                   | Pi output                                 | Reason                                                                                                                                                                                                                                     |
| ------------------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| The 51 common required tokens               | Keep unchanged                            | Token names and roles match.                                                                                                                                                                                                               |
| Missing `thinkingMax`                       | Copy `thinkingXhigh`                      | This is Pi's documented fallback. Materializing it makes the file complete.                                                                                                                                                                |
| Missing `scrollbarThumb`                    | Copy `selectedBg`                         | This is Pi's documented fallback. Materializing it makes the file complete.                                                                                                                                                                |
| `pythonMode`                                | Remove                                    | Pi has no Python-mode token.                                                                                                                                                                                                               |
| All 14 `statusLine*` tokens                 | Remove                                    | Pi has no matching theme tokens. Status/powerline styling is separate.                                                                                                                                                                     |
| Legacy `link`                               | Remove                                    | Pi uses `mdLink`; all 52 source values already equal `mdLink`.                                                                                                                                                                             |
| Legacy `toolText`                           | Remove                                    | Pi uses `toolOutput`, which is already present in all affected files.                                                                                                                                                                      |
| Top-level `symbols`                         | Remove                                    | Pi rejects it. This affects only the two Poimandres themes.                                                                                                                                                                                |
| OMP `$var` references                       | Strip the leading `$`                     | Pi resolves a variable by its exact key. Only `onyx` uses this incompatible form.                                                                                                                                                          |
| A value that references another color token | Resolve it to that token's variable/value | Pi variable references can point only into `vars`. In `light-prism`, four retained values reference color token `muted`; replace them with `slate`, because `colors.muted` is `slate`. The dropped `statusLineContext` has the same issue. |
| Eight-digit `#717cb425`                     | Use `#717cb4`                             | Pi accepts six-digit RGB and its runtime parser rejects other lengths. This affects only the two Poimandres themes. OMP's own `Bun.color` path emits the RGB part and ignores that alpha byte.                                             |
| OMP `$schema` URL                           | Replace with Pi's schema URL              | Editor checks must target the actual consumer schema.                                                                                                                                                                                      |

Pi's resolver applies variable references only through the `vars` object, and its hex parser requires exactly six digits. Source: [Pi theme implementation](https://github.com/earendil-works/pi/blob/afae6a1a998dbdfacc1004cbd26c6c6a99395bb2/packages/coding-agent/src/modes/interactive/theme/theme.ts). OMP also resolves normal references through `vars`; its current resolver does not strip `$`. Source: [OMP color resolver](https://github.com/can1357/oh-my-pi/blob/45e12e5bb758198a920c6070e7e64cb33b21beac/packages/coding-agent/src/modes/theme/color.ts).

A local audit applied these rules to all 98 `defaultThemes` files. The installed `@earendil-works/pi-coding-agent` 0.84.1 runtime loaded all 98 transformed files in true-color mode with no error.

## Maintainable update design

Keep updates deterministic and reviewable:

1. Store the exact OMP commit and source registry path in `upstream.json`.
2. Use an update script to parse `defaults/index.ts`. Fetch only its 98 exported JSON files. Do not infer the set from a directory listing.
3. Apply the explicit transform table above. Fail on a new unknown token, unresolved reference, invalid color, duplicate theme name, or registry/file mismatch.
4. Run every generated file through the installed Pi runtime loader. Record the source commit and generated file hashes.
5. Copy the pinned OMP `LICENSE` and update the source links in `README.md`.

Do not load OMP as a runtime dependency. The package needs only generated JSON files. This removes third-party code execution and prevents upstream schema changes from silently breaking Pi startup.

## Open decisions and blocker

1. **Theme selection is required.** Current settings select `everforest-dark-hard`. OMP does not provide that theme name. Removing `pi-curated-themes` without changing `theme` will leave the selected theme unavailable. A close name is `dark-forest`, but it is not an Everforest port.
2. **Scope needs confirmation only if base overrides are wanted.** The safe scope is the 98 `defaultThemes` entries. Add OMP `dark` and `light` only if overriding Pi's built-in names is an explicit goal.
3. **The Poimandres symbol preset cannot move with the colors.** Pi themes do not support OMP's `symbols` object. The colors remain usable after that metadata is removed.
