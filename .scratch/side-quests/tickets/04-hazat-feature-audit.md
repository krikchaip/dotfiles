# HazAT Feature Audit

Type: grilling
Status: resolved

Domain terms follow the [specification](../spec.md#domain-model): parent agent and sub-agent name actors; main quest and side quest name tasks.

## Question

Walking through `hazat/pi-interactive-subagents`' README in order, which features and behaviors should `side-quests` retain, simplify, replace, or exclude, and which earlier wayfinding decisions should change?

## Comments

- Use the upstream README as the concrete top-down outline instead of designing behavior from first principles.
- HazAT is the default runtime and UX baseline. Retain each feature unless the audit explicitly simplifies, replaces, or excludes it.
- For each section, record upstream behavior, `side-quests` disposition, replacement behavior when applicable, and rationale.
- Inspect source when README wording is incomplete or disagrees with current behavior.
- [Agent Interface](01-agent-interface.md), [Pane Layout Modes](02-pane-layout-modes.md), and [Agent Configuration](03-agent-configuration.md) remain the baseline, but this audit may explicitly revise them.
- Consult `tintinweb/pi-subagents` only when a HazAT section reaches tool compatibility or inspires a targeted addition; defer a narrow compatibility-delta check until the HazAT audit is complete.
- Exact session-directory structure, retention, and acceptance tests may remain dedicated follow-up tickets.
- Name the shared tmux window with the first hyphen-delimited segment of the parent Pi session UUID. Treat that short name as display-only; retain the full parent session ID as ownership identity and target the canonical tmux window ID for every operation.
- Creating or resuming a sub-agent pane does not steal tmux focus from the parent agent. The user switches to the shared sub-agent window explicitly.

### How It Works — retained with targeted replacements

- Retain asynchronous launch, one isolated Pi process and persistent session per sub-agent, concurrent launches, a restrained above-editor status widget, and terminal completion/failure delivery that wakes the parent model. Keep a recoverable interactive turn failure local.
- Replace HazAT's `subagent` tool with the resolved `Agent` interface.
- Replace independent multiplexer placement with one shared sub-agent tmux window per parent session and the resolved `binary` or `ternary` layout.
- Support Pi on tmux only; exclude HazAT's other runtimes and multiplexer backends.
- Retain HazAT's child-written activity snapshots and one-second parent polling. Tiny per-child reads favor deterministic behavior over `fs.watch` complexity and missed-event recovery. Add a periodic child heartbeat so a readable but frozen snapshot eventually becomes unhealthy; heartbeat age measures child event-loop liveness, never task progress.
- Retain Pi activity states `starting`, `active`, `waiting`, and `stalled`. Exclude `running`, which is only HazAT's fallback for runtimes without Pi snapshots. Completion and terminal failure are notification outcomes rather than persistent widget states; a recoverable interactive turn failure returns its live row to `waiting`.

### Install — simplified to tmux-only package

- Package under `packages/side-quests` using the repository's existing Pi package structure.
- Retain startup environment validation and focus-preserving pane creation.
- Outside tmux, warn once, register nothing, and remain inert.
- Exclude cmux, Zellij, WezTerm, `PI_SUBAGENT_MUX`, and all backend-selection logic.
- Exclude `PI_SUBAGENT_SHELL_READY_DELAY_MS`; launch Pi directly as the tmux pane command instead of opening an interactive shell and sending keystrokes.

### What's Included — resolved with a smaller surface

- Replace HazAT's parent-facing tools with the single resolved `Agent` tool; fold resume into `Agent.resume` and expose the discovered catalog through the parent system prompt instead of `subagents_list`.
- Do not expose a model-callable `subagent_interrupt` tool and do not propagate parent-agent interruption. Never inspect or replay terminal keys, subscribe to the main run's abort signal for broadcasting, or synthesize an interrupt through `pi.events`. The parent live-status UI has no interrupt action. To interrupt a child run, the user jumps to that child pane and invokes Pi's normal effective `app.interrupt` action there. Parent interruption affects only the parent.
- Exclude HazAT's `/plan`, `/iterate`, and `/subagent` commands. Existing `home/dot_pi/agent/extensions/branch-merge.ts` owns interactive branch/fork/merge workflows, so `side-quests` does not duplicate them. Its only parent command is the `/side-quests` live-pane navigator specified below.
- Exclude all bundled agents. Discovery uses only the resolved project and global scopes.
- Replace the model-callable child `subagent_done` tool with a child-only `/subagent-done` command. Every child Pi pane is terminal-interactive; lifecycle controls command availability and persistence, not whether the pane accepts input. Dynamically register the command at startup for an initially interactive child or immediately when an autonomous child accepts a direct non-command prompt and becomes permanently interactive. Restore registration from persisted lifecycle state after reload, adoption, or reopen. Do not register or show it while autonomous; reject `/subagent-done` and `/subagent-done ...` through an autonomous input guard without sending text to the model or promoting lifecycle. Never register it in the parent or expose it to the model. The command accepts no arguments and renders `Usage: /subagent-done` when arguments are present. During streaming or another active agent turn, keep the child open and tell the user to wait or interrupt first. While idle, atomically write the trusted completion marker, deliver the final assistant response as completion, retain the resumable session and any unanswered parent request, and shut down the child.
- Rename HazAT's child-only `caller_ping` model tool to `ask_parent`. Treat it as a reserved control capability above frontmatter tool policy: register and activate it in every child after resolving `tools` and `disallowed_tools`, so neither omission from `tools` nor inclusion in `disallowed_tools` can disable it. It remains available after interactive takeover.

### Async Subagent Flow — retained with compatibility handoffs

- Retain asynchronous launch, concurrent children, continued main-session interaction, live status, and terminal completion or failure delivery that wakes the parent model. A recoverable failed turn in a healthy interactive child remains local and does not produce a parent delivery.
- Parent interruption never changes child state. On parent quit or session replacement (`new`, `resume`, or `fork`), first mark teardown as expected, then terminate every tracked child pane owned by that parent session and retain all child session files. Children also monitor their unique parent ownership identity and self-terminate if the parent process disappears before graceful cleanup, preventing orphan agents after pane closure, crash, or forced process exit. Do not emit child completion or closure handoffs during expected owner teardown.
- Retain HazAT's result extraction and strengthen its failure distinctions. A successful handoff contains the child's final assistant response and canonical session path, not its full transcript. An exhausted provider or agent-loop error is terminal for an autonomous child and reports the underlying error plus retry/resume guidance. The same turn-scoped error in a healthy interactive child stays visible in its pane, returns the child to waiting, and does not notify or wake the parent. A fatal or nonzero process exit is terminal for either lifecycle; include the current-run final assistant response when available and otherwise use a fallback diagnostic. Never treat an earlier assistant message as a usable result for a terminal failure. Cancellation reports cancellation. Add `closed` for a pane that disappears without a trusted terminal marker; include the final assistant response when available and the session path, but do not claim completion or user intent. Every terminal handoff includes the session path when one exists.
- Retain HazAT's restrained colored completion message and collapsed/expanded views. Expansion uses Pi's standard `app.tools.expand` action and renderer `options.expanded` state. Render its effective user-configured binding with `keyHint("app.tools.expand", ...)`; never display or register a hard-coded `Ctrl+O` shortcut.

### In-progress Status Updates — retained with stronger liveness

- A child-only companion entrypoint in the `side-quests` package subscribes to Pi lifecycle, provider, streaming, tool, input, and shutdown events. The parent-orchestration entrypoint remains inert in child sessions and registers no spawning surface there.
- The companion atomically replaces one small, schema-versioned JSON snapshot per live child. The snapshot carries the running-child ID, monotonic sequence, event timestamp, heartbeat timestamp, latest event, phase, active scope, tool details, and permanent interactive-takeover state. Streaming and tool-update writes may be throttled; lifecycle boundaries and takeover writes are immediate.
- The parent reads each snapshot once per second and validates its schema and running-child ID. In the same loop, verify every canonical tmux pane ID still exists. Do not use `fs.watch` or install server-global tmux hooks.
- Fix HazAT's destroyed-surface polling gap: when a tracked pane disappears, allow one additional poll for a racing terminal sidecar. A trusted `done`, autonomous-completion, cancellation, or terminal-error marker wins; otherwise terminate tracking as `closed`, wake the parent, remove the widget row, reflow remaining panes, and preserve the session for `Agent.resume`. `closed` is the fallback for any unmarked disappearance, including `/quit`, EOF, clean process exit without semantic completion, `tmux kill-pane`, whole-window closure, or an unrecorded crash. An outstanding `ask_parent` request is nonterminal and does not suppress `closed`; preserve its mailbox so a later `Agent.resume` can answer while reopening the session. A captured fatal or nonzero process exit remains `failed`, not `closed`; an interactive turn-scoped provider/agent-loop error is nonterminal while the Pi process remains healthy. Expected pane removal during parent shutdown emits no notification; loss of the enclosing tmux session or server normally ends the parent too, leaving no process to notify.
- Preserve the 60-second watchdog for snapshots that never appear, are missing, invalid, belong to another child, or have a stale heartbeat. A current heartbeat keeps long-running `active` and `waiting` phases healthy regardless of their duration. Do not implement a task-progress timeout.
- `starting`, `active`, and `waiting` transitions update only the restrained widget. `stalled` and `recovered` additionally wake the parent model for autonomous children. Initially interactive children and permanently taken-over children remain widget-only.
- Extend HazAT's view-only widget into a focusable live-child navigator while preserving its restrained blue border, title/count header, `HH:MM:SS` elapsed-time prefix, per-call task label, frontmatter `display_name` agent label with filename fallback, a right-side activity column, truncation, and narrow-terminal behavior. The widget uses available terminal width rather than a fixed sample width. Every row has two visible cells of inner padding at each border and two visible cells between the elapsed-time, agent/task, and activity columns. Compute common column starts across all rows and pad shorter values within their columns so each column's first visible character aligns vertically and two cells remain before the right border. When a parent reply is needed, render `reply needed` after activity, such as `active · reply needed`. Passive mode adds no bright controls or permanent selection chrome.
- Register one parent command, `/side-quests`, to enter navigation mode; with no live children it only notifies the user. Do not add a global shortcut in MVP. Navigation keeps the same above-editor box and marks only the selected row with a restrained accent chevron. Effective `tui.select.up` and `tui.select.down` actions move the highlight, effective `tui.select.confirm` jumps to the selected pane, and effective `tui.select.cancel` leaves navigation. A scoped literal `d` requests close; render that actual key through `rawKeyHint` rather than duplicating a label string. No navigation key affects the ordinary editor outside this mode.
- Jump explicitly switches only the invoking tmux client to the selected child's stable window and pane IDs, then exits navigation. Launch and resume remain focus-preserving. Close shows a confirmation naming the child and warning that its active run will stop while its session stays resumable. Confirmation writes a trusted user-cancellation marker before pane removal so the outcome is `cancelled`, not `closed`, then removes the row and reflows while keeping navigation on the nearest surviving row. If none remain, exit navigation and clear the widget. The navigator provides no interrupt action.
- Keep selection keyed by child ID rather than row index. If the selected child terminates independently, move to the nearest surviving row; if rows reorder or labels duplicate, selection remains attached to the same child.
- Keep status display active whenever live children exist. Exclude HazAT's package-local `config.json` status toggle.

### Child Tools Widget — replaced by an identity widget

- Keep HazAT's compact above-editor widget inside every child pane, but replace its available/denied-tool dashboard with one restrained identity box. Put `[agent label]` in the top border. Render one content row with `HH:MM:SS`, task label, and `autonomous|interactive`, plus `· reply pending` when a request is pending. The corresponding parent row shows `reply needed`; both indicators remain independent of activity state.
- Resolve `agent label` to frontmatter `display_name` when present, otherwise the canonical filename stem. Never render both. Resolve `task label` to the current required `Agent.description`; update it after live continuation or reopened resume. Give the content row two visible cells of horizontal padding and two visible cells between columns; adapt box width to the child pane.
- Remove the tools list, denied-tools list, expansion state, and `Ctrl+J` shortcut. On narrow terminals, truncate the task label before agent identity or lifecycle/request state while preserving spacing and borders.

### `caller_ping` — replaced by mailbox-backed `ask_parent`

- Use separate nonterminal request and response mailbox files; never overload a terminal `.exit` sidecar. Store schema version, full owner and child IDs, unique request ID, session path, message, and timestamp under the child's private runtime directory. Use restrictive permissions, atomic temporary-file replacement, matching-ID validation, and persisted request-ID deduplication.
- Permit one outstanding request per child. The first `ask_parent` call atomically writes the request and returns an ordinary successful tool result without `terminate: true` or `ctx.abort()`. Sibling tools in the same batch execute normally, and the child continues its turn without waiting. Reject every later `ask_parent` call until the first request receives a matching accepted response.
- Keep the pane and Pi process alive while work continues. Do not suppress normal autonomous completion because a request is pending; a child may complete and close before the parent answers, and its unanswered request remains persisted. A `closed` handoff explicitly states when that unanswered request remains. The parent poller reads the request, injects one custom help message into the parent session, and wakes the parent without reflowing a live pane.
- A new child receives the launch `Agent.prompt` as a normal user-role message after any inherited conversation. `Agent.resume` is the only response surface, and every resume `prompt` is a persisted custom message rather than a normal user-role message. Its `resume` path corresponds to HazAT's `sessionPath`, `prompt` to `message`, and `description` to `name`; `interactive` corresponds to the inverse of `autoExit` only on a new launch. Reject a resume containing `subagent_type`, `inherit_context`, or `interactive`. For a live idle child, atomically write the matching response and let the child companion inject the custom message immediately and trigger a turn. For a live active child, queue the custom message as `steer` so it arrives after the current tool batch without aborting. For a closed child, reopen its persisted session in a new focus-preserving pane and inject the custom message as the first continuation while resolving the pending request.
- Lifecycle mode, parent-request state, and activity are orthogonal. The parent widget shows `reply needed`; the child widget shows `reply pending`. After creation, only an accepted non-command prompt submitted from the live child terminal with Pi input source `interactive` permanently promotes autonomous lifecycle to interactive. Interactive terminal input may start work while the parent request remains pending; it never cancels that request. Resume, editing, typing, pasting, navigation, extension commands, ordinary parent continuation, and other extension-injected guidance do not promote lifecycle. Interactive lifecycle never demotes. Clear the pending request only after the matching response is accepted. Thus autonomous or interactive children may both be idle or active while a reply is pending.
